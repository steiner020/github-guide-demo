仓库中的需求、数据与角色均为虚构，用于演示 GitHub 协作流程。

快速开始

从一段 Markdown 会议纪要开始，在本地或 Codespaces 中跑通完整流程。默认分支已包含示例数据，不需要模型账号。

安装与运行

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

python -m src.requirements_parser examples/meeting-notes.md

如果只想看输出，可以直接打开 examples/meeting-notes.md，对照终端的结构化结果。

没有本地环境时，在仓库页面选择 Code → Codespaces，等待容器启动后按同一组命令执行。

导入会议纪要

解析器识别二级标题作为故事边界，并把标题下的列表项收集为该故事的素材。支持 - 与 * 两种列表符号。

输入行为
二级标题新建一条故事草稿
标题下的列表项追加为故事素材
没有标题的正文忽略，并提示补充结构

生成用户故事

每条输出包含标题与素材列表。v0.1.0 不负责润色，它只做确定性拆分；生成措辞由提示词模板约束，避免把猜测写成事实。

## 纪要导入

- 支持粘贴 Markdown 与纯文本
- 单次不超过 20 万字符

验收标准

好的验收标准必须可观察、可测试。建议同时覆盖主路径和异常路径，例如“导入失败时保留原文”。

  • 每条标准都能在评审会上演示或测试。
  • 避免“体验流畅”“性能良好”这类无法判定的描述。
  • 缺少成功指标时，先列出待确认问题。

命令行

# 从文件读取
python -m src.requirements_parser examples/meeting-notes.md

# 运行测试
python -m pytest -q

提示词模板

提示词位于 prompts/story-template.md，要求模型只使用输入材料中的信息。CI 会做一次字段冒烟检查，防止模板误删关键段落。
